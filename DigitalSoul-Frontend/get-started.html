Get Started with DigitalSoul

Turn repeated desktop work into deterministic, verifiable workflows. DigitalSoul observes consented actions and compiles them into strictly typed DAGs executed via browser-use CDP sessions.

⚡ Zero Hallucinations 🛡️ Agent-Side Approval Gates 🌐 browser-use 0.13.11 CDP 🧠 OmniRoute 127.0.0.1:20128

01 System Prerequisites

Before running DigitalSoul locally, ensure your system has the following requirements installed:

  • Operating System: Windows 10/11 (with PowerShell 7+ recommended) or Linux/macOS.
  • Python Environment: Python 3.11 or Python 3.12 64-bit with pip and venv.
  • Browser: Google Chrome or Microsoft Edge (browser-use connects directly via Chrome DevTools Protocol).
  • Node.js (Optional): Node 18+ if building or packaging the browser observer extension.

02 Clone & Environment Setup

Set up an isolated Python virtual environment and install dependencies in editable mode:

PowerShell (Windows)
# 1. Open PowerShell and navigate to the project directory cd "C:\Projects\DigitalSoul" # 2. Create isolated Python virtual environment python -m venv .venv # 3. Activate the virtual environment .\.venv\Scripts\Activate.ps1 # 4. Install dependencies and testing harness python -m pip install -e '.[test]'
Note on Dependencies: We deliberately use browser-use with native CDP/Actor APIs. Do not install Playwright, as DigitalSoul enforces strict deterministic execution without synthetic browser emulators.

03 Launch M2 Execution Backend

The M2 execution backend runs as a local FastAPI service on 127.0.0.1:7777. It requires loading an explicitly admitted, reviewed workflow plan:

PowerShell
# Launch standalone M2 daemon with the admitted valid test workflow .\.venv\Scripts\python.exe -m agent.ghost.api.m2_app --workflow contracts/fixtures/workflow.valid.json
Security & Admission Architecture

The host binds exclusively to 127.0.0.1:7777. HTTP clients cannot upload unvetted execution scripts and self-grant trust. All requests require a DPAPI-protected Bearer token derived through the local desktop identity:

# Retrieve your local authentication token $token = .\.venv\Scripts\python.exe -m agent.ghost.safety.credentials --data .ghost

04 Connect OmniRoute AI Gateway

OmniRoute provides local LLM inference and model routing at http://127.0.0.1:20128/v1:

PowerShell
# 1. Start the local loopback OmniRoute daemon .\scripts\start-omniroute.ps1 -Probe # 2. Run the diagnostic connection probe .\.venv\Scripts\python.exe -m agent.ghost.integrations.connections --browser --inference --output .ghost/connection-report.json

05 Load the Browser Extension Observer

The semantic observer records repeated actions within your web applications while redacting sensitive fields:

  1. Open Google Chrome or Microsoft Edge and navigate to chrome://extensions.
  2. Enable Developer mode in the top-right toggle.
  3. Click Load unpacked and select the extension/ folder in this repository.
  4. Click the DigitalSoul icon in your toolbar to verify the observer status ("Observing - Redaction active").

06 Dispatch Your First Workflow Run

Trigger a safe dry run through PowerShell using authenticated REST invocations:

PowerShell
$token = .\.venv\Scripts\python.exe -m agent.ghost.safety.credentials --data .ghost $headers = @{ Authorization = "Bearer $token" 'Idempotency-Key' = [guid]::NewGuid().ToString() } $body = @{ workflow_version = 4 mode = 'dry_run' parameters = @{} } | ConvertTo-Json Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:7777/api/v1/workflows/wf_at_risk_seg/runs' -Headers $headers -ContentType 'application/json' -Body $body
